# 상품 이미지·상세페이지 편집

관리자 상품 관리(`/admin/shop`)에서 사용한다.

1. 대표 이미지 직접 업로드에서 JPG·PNG·WebP 파일(최대 3MB)을 선택한다. 기존 HTTPS 이미지 주소 입력도 유지한다.
2. 상품 요약을 작성하고 상세페이지에 제목·본문·이미지 블록을 추가한다. 최대 30개이며 ↑/↓로 순서를 바꾸거나 삭제할 수 있다. 이미지마다 대체 설명과 캡션을 편집한다.
3. 저장 전 미리보기에서 모바일 폭/넓은 보기로 확인한다. 실제 쇼핑몰과 동일한 상세 렌더러다. 미리보기 내용은 저장 전에는 공개 상품에 반영되지 않는다.
4. 상품 저장 후 쇼핑몰의 상품 상세 URL에서 확인한다. 판매 중을 해제하면 기존과 같이 비공개 상태로 저장한다.

## 저장·보안

대표 이미지와 상세 이미지는 Supabase Storage `product-images` 공개 버킷에 저장한다. 상품용 공개 이미지이며 업로드 자체로 URL에서 조회 가능하다. 판매 비공개는 상품 조회 제한이며 이미지 파일의 비공개를 뜻하지 않는다.

웹 앱은 서비스 키 없이 로그인한 관리자의 세션으로 업로드한다. API와 Storage INSERT 정책 모두 관리자 권한을 요구한다. 경로는 회원 UUID/무작위 UUID.webp, 원본 파일명은 저장하지 않으며 덮어쓰기를 허용하지 않는다. 버킷 생성/권한은 `db/product-storage.sql`, 콘텐츠 스키마는 `db/product-content.sql`이며 `npm run db:apply`에 포함된다.

서버는 multipart 요청 4MB, 원본 파일 3MB, 입력 4천만 화소 제한을 적용한다. MIME만 믿지 않고 실제 PNG/JPEG/WebP를 해석해 정지 이미지만 허용하고, 방향을 보정한 뒤 WebP로 다시 인코딩한다. 최대 2000×6000 범위 안에서 비율을 유지해 축소하고 원본 메타데이터를 저장하지 않는다. SVG·GIF·동영상·위장 파일은 거부한다.

상세는 제한된 JSON 블록이고 임의 HTML은 실행하지 않는다. 제목 200자, 본문 블록 5,000자, 캡션 500자, 이미지 HTTPS URL만 허용한다. 화면의 텍스트는 React가 이스케이프한다. 기존 요약과 이미지 URL은 유지한다. 구버전 관리자 요청에서 detailBlocks를 생략해도 이미 저장한 블록을 지우지 않는다.

주문 생성 시 상세 블록을 주문 스냅샷에 복사하므로 이후 상품을 편집해도 주문 상세는 바뀌지 않는다. 과거 주문에는 당시 없던 새 상세를 소급 삽입하지 않는다. 이미지 제거는 편집 내용에서 참조를 제거하며, 과거 주문에서 사용할 수 있는 Storage 파일을 자동 삭제하지 않는다. 저장하지 않고 업로드만 한 미사용 파일의 정기 정리는 후속 운영 작업이다.

## 검증

이미지 디코딩·재인코딩·파일 제한·콘텐츠 검증과 주문 스냅샷 테스트를 추가했다. 테스트 런너는 Windows Node/PGlite 병렬 실행 중 발생한 네이티브 V8 종료를 피하기 위해 파일 단위로 순차 실행한다. 테스트의 검증 항목은 그대로 유지한다.

`scripts/verify-commerce.ts --test-account`는 실제 관리자 업로드, 일반 회원 업로드 거부, 공개 WebP 조회, 블록 저장과 주문 스냅샷을 검증하고 QA 이미지·계정을 정리한다. 브라우저 자동화는 현재 도구 실행 경로 오류로 수행하지 못했다. API·실제 DB 검증과 화면 조작 검증을 구분한다.
