# 언어 모드

- 기본 언어는 브라우저 언어와 관계없이 한국어(`ko`)다. 상단에서 English(`en`)·日本語(`ja`)를 선택할 수 있다.
- 선택은 브라우저의 `jmusdt-locale` 쿠키에 1년간 저장한다. 같은 서비스의 페이지 이동·새로고침·로그인 후에도 유지한다. 지원하지 않는 값은 한국어로 처리한다.
- 서버 렌더링과 HTML `lang`, 설명 메타데이터, PWA manifest, 이메일 확인 진입 페이지와 오프라인 화면도 선택 언어를 따른다. 서비스 URL은 유지한다.
- 화면 문구와 앱 오류 메시지는 `src/lib/i18n-messages.ts`의 영어·일본어 사전에서 관리한다. 현재 등록한 세 상품의 이름과 안내 문구도 포함한다. 사용자 이름·주소·추천코드·입력값과 DB 원문은 변경하지 않는다. 새로 작성한 상품 설명·커스텀 등급 등 사전에 없는 콘텐츠는 등록된 원문을 표시한다.
- 날짜 표시는 선택 언어의 형식을 사용하며 업무 시간대는 한국시간(`Asia/Seoul`)이다. P·USDT 금액 계산, 주문 요청, 추천/후원/맘·데일리·회사 풀 정책은 언어와 무관하다.

## 문구 추가

클라이언트 컴포넌트에서는 `useI18n()`의 `tr`을, 서버에서는 `await serverI18n()`의 `tr`을 사용한다. 기본 한국어 문구를 키로 추가하고 영어·일본어를 순서대로 작성한다. 동적 값은 문자열을 이어 붙이지 말고 자리표시자를 사용한다.

```tsx
const { tr } = useI18n();
tr("구매가 완료되었습니다. 주문번호 {0}", { 0: order.id });
```

API 응답의 기존 한국어 오류는 화면에서 번역한다. 오류에 따른 분기와 감사 기록에 사용하는 원문은 유지한다. 금액·수량·상품 유형과 고정 확인 문구를 번역된 값으로 서버에 보내지 않는다.

`tests/i18n.test.ts`는 번역 누락과 자리표시자 일치를 확인한다. `tests/i18n.spec.ts`는 언어 유지·입력 유지·가격·배송 요청·관리자·확인 페이지·오프라인 표시를 검증한다.

## 운영 연결

페이지 연속 검증에서 기존 Supabase 세션 풀(5432)의 `EMAXCONNSESSION`, `pool_size: 15` 한도 도달을 확인했다. Vercel 운영 `DATABASE_URL`은 같은 프로젝트의 트랜잭션 풀(6543)로 전환하고 인스턴스별 애플리케이션 풀을 3개로 제한한다. 로컬 워커·스크립트의 기본 설정은 유지한다. 포트 전환 전 TLS 연결과 실제 트랜잭션·트랜잭션 단위 advisory lock 동작을 검증했다.
