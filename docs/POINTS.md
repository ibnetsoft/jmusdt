# 포인트와 USDT 전환

2026-10-28 적용. 지갑의 `/points`에서 USDT ↔ 포인트를 전환한다.

- **1 USDT = 1 P**, 양방향, 전환 수수료 0. 소수점 6자리까지 지원한다.
- USDT는 기존 `balances`, 포인트는 `point_balances`에 독립 보관한다. 사용 가능한 잔액만 전환하며 출금 예약액은 사용할 수 없다.
- `/shop` 상품 가격과 신규 주문은 포인트 단위다. 포인트가 부족하면 먼저 USDT를 전환한다. 쇼핑 결제가 USDT를 자동 차감하지 않는다.
- 기존 상품 숫자 가격은 1:1로 포인트 가격이 되며 버전을 올려 이전 견적으로 결제하지 못하게 한다. 기존 USDT 주문·원장 기록은 USDT로 보존한다.
- USDT 입출금·회원 송금은 기존 USDT 기능을 유지한다. 포인트는 온체인 토큰이 아니며 별도 출금 주소를 만들지 않는다.

## 데이터와 검증

`npm run db:apply`는 `schema.sql → commerce.sql → points.sql`을 하나의 트랜잭션으로 적용한다. 기본 자산을 USDT로 추가해 기존 거래·원장을 보존한다. 전환은 사용자 확인 후 한 DB 트랜잭션에서 원자적으로 처리한다.

`wallet_swap`은 계정 잠금, 출발 잔액 확인, 1:1 차감/증가, 자산별 거래 2건·원장 4행, 전환 기록을 함께 저장한다. 같은 요청키/같은 내용은 재지급 없이 기존 결과를 반환하고 다른 내용 재사용은 거부한다. 브라우저 DB 역할은 함수를 직접 실행하거나 잔액을 수정할 수 없다. 소수점 계산에 Number를 사용하지 않는다.

원장은 batch뿐 아니라 **자산별 합계도 0**이어야 한다. USDT 차감과 POINT 증가를 단순 상쇄하지 않고 각 자산의 전환 준비 계정을 사용한다. 관리자 대사는 USDT 채무 + 1:1 환급 가능한 포인트 채무 + 수수료 + 쇼핑 매출을 포함한다.

`tests/points.test.ts`는 소수점 6자리 왕복 전환, 잔액 부족, 중복·충돌, 차단 회원, DB 역할 제한과 자산별 균형을 확인한다. 쇼핑 테스트는 포인트 전환 후 결제하며 포인트만 차감되는지 확인한다. `scripts/verify-commerce.ts --test-account`는 API 접근과 실제 PostgreSQL 왕복 전환·결제를 검증한다. 테스트 자금·전환·주문은 롤백되며 임시 계정은 정리된다.
