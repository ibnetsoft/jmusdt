# 주문 관리·취소·전액 환불

## 사용

- 관리자가 상품별 배송 유형을 실물 배송 또는 배송 불필요로 지정한다. 실물 상품은 결제 전 수령인·연락처·주소가 필수이며 배송 요청사항은 선택이다. 배송비는 별도로 계산하지 않는다. 기존 상품은 유형이 미지정 상태로 보존되며, 관리자가 유형을 저장하기 전까지 새 쇼핑몰 목록에서 제외된다.
- 배송 정보가 있는 주문은 관리자 주문 상세에서 배송 준비 → 배송 중 → 배송 완료로 처리한다. 배송 중/완료에는 택배사와 송장번호가 필요하다. 회원은 구매 내역에서 배송지와 송장번호를 확인할 수 있다.
- 취소가 접수되면 배송 정보 변경이 차단된다. 배송 중이나 완료된 주문도 고객이 취소를 요청할 수 있으며 관리자가 반품·배송 상황을 확인한 후 승인 또는 반려한다. 자동 반품·부분 환불은 지원하지 않는다.
- 배송 정보는 별도 테이블에 보관하며 Data API 역할의 직접 접근을 차단한다. 서버는 본인 주문 또는 관리자 권한을 확인해 조회한다. 같은 구매 요청키에 다른 배송 정보를 보내면 충돌 처리한다.

- 관리자 콘솔의 **주문 관리** 또는 `/admin/orders`에서 주문번호·상품·회원으로 검색하고 상태별로 조회한다. 최근 결과 최대 200건을 표시한다.
- 주문 상세에서 결제 당시 상품·단가·수량·금액·자산과 취소 요청 사유를 확인한다.
- 관리자가 처리 사유를 입력하고 **취소 승인·환불 검토 → 취소 승인 및 전액 환불 확정**을 누르면 전액 반환·재고 복구가 함께 완료된다. 고객 요청이 없어도 관리자 직접 취소가 가능하다.
- 고객은 쇼핑몰 구매 내역에서 사유를 입력해 취소를 요청한다. 요청만으로 환불되지 않으며, 관리자 승인 전에는 `취소 승인 대기`다. 관리자는 요청을 반려할 수 있고 사유는 감사 기록에 남는다.
- 신규 주문은 **포인트**로 환불한다. 과거 USDT 직접 결제 주문은 기록된 원 결제 자산인 USDT로 환불한다. 환불 시 자동으로 USDT↔포인트 전환을 하지 않는다.

## 처리와 권한

상태는 `paid → cancellation_requested → cancelled`이며 반려하면 `paid`로 돌아간다. 직접 취소는 `paid → cancelled`다. 주문 전체 취소·전액 환불만 지원하며 부분 환불·부분 수량 취소는 지원하지 않는다. 배송 상태는 주문 취소 상태와 별도로 관리한다.

기존 서버 관리 `adminConsole` 관리자 권한이 주문 조회·승인·반려를 허용한다. 외부 출금 권한을 추가하지 않으며, 환불은 주문에 저장된 회원·자산·금액·수량으로만 제한된다. 고객은 자신의 주문만 취소 요청할 수 있다. 로그인과 Origin 검사를 유지한다.

`shop_refund`는 회원 → 주문 → 상품 순서로 잠근 뒤 잔액 반환, 재고 복원·버전 증가, 별도 환불 거래, 자산별 균형 원장, 주문 상태와 감사 기록을 한 DB 트랜잭션으로 처리한다. 원 구매와 원장은 삭제·수정하지 않는다. 현재 상품 가격·판매 여부와 무관하게 구매 당시 금액과 수량을 사용한다. 차단된 회원의 주문도 관리자 환불은 가능하다.

이미 취소된 주문을 다시 승인하면 기존 환불 거래를 반환한다. 새로운 요청·관리자·사유로 재시도해도 잔액과 재고가 다시 증가하지 않는다. 브라우저 역할은 DB 함수를 직접 실행할 수 없다.

## 적용·검증

`npm run db:apply`는 기존 스키마 이후 `db/refunds.sql`을 적용한다. 기존 주문은 `paid`가 되며 이전 거래 자산은 유지한다. 기존 스키마 재적용도 `refund` 거래를 허용하도록 갱신했다.

`tests/refunds.test.ts`는 포인트 반환·재고 복구·중복 승인·가격 변경/판매 중지·차단 회원 환불·원 구매 보존·원장 균형·일반 DB 역할 차단·USDT 과거 주문·재적용을 확인한다. `scripts/verify-commerce.ts --test-account`는 실제 관리자 API 접근과 실제 PostgreSQL 결제→환불을 검증한다. 테스트 결제·전환·환불은 롤백으로 종료해 가짜 자금이나 주문을 남기지 않는다.
