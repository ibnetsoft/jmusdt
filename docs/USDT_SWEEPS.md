# TRC20 USDT 지갑 모으기

어드민의 **USDT 모으기**(`/admin/sweeps`)에서 회원 보관 주소의 실제 USDT를 서버에 지정한 회사 지갑으로 일괄 이동합니다. 앱 회원의 USDT·포인트 잔액이나 원장을 차감하는 출금이 아닙니다.

## 운영 흐름

1. 회원·이메일·주소를 검색하고 **이 페이지 온체인 잔액 조회**를 누릅니다. 10개 주소씩 표시하며 확정 USDT와 현재 TRX를 별도로 조회합니다. 실패·시간 초과는 0이 아닌 미확인으로 표시합니다.
2. 잔액이 확인된 지갑을 개별 선택하거나 현재 페이지의 잔액 보유 지갑을 전체 선택합니다. 한 번에 최대 10개를 검토·승인할 수 있습니다. 다음 페이지도 같은 방식으로 처리합니다.
3. **회수 검토**에서 네트워크, 고정 회사 주소, 지갑별 USDT, 회원·회사 TRX, 가스 보충 상한, 계약 수수료 한도, 회사 최소 TRX 보유량을 확인합니다. 검토 유효기간은 5분입니다. 이 단계는 서명·전송하지 않습니다.
4. 회수 사유와 `USDT 회수` 문구를 입력해 승인합니다. **SUPER_ADMIN + AAL2(2단계 인증)**가 필요합니다. 일반 관리자 콘솔 권한은 조회·검토까지만 허용합니다.
5. 별도 워커가 필요한 TRX를 보충하고 확정 영수증을 기다린 뒤 승인 수량의 USDT를 전송합니다. 브라우저를 닫아도 워커가 진행합니다. 이력은 5초마다 갱신되며 두 단계의 TX 링크를 표시합니다.

승인 당시 수량만 이동하므로 이후 추가 입금은 다음 검토 대상입니다. 회사 주소는 회원 입금 주소와 분리하며, 회원 주소의 파생 인덱스와 수탁 서비스의 실제 파생 주소가 일치해야 서명됩니다.

## 설정과 실행 환경

마이그레이션은 회수를 **비활성** 상태로 생성합니다. 어드민에서 건당 TRX 보충 상한(기본 25 TRX, 범위 0~100 TRX), 회사 최소 보유량(기본 50 TRX), 활성/일시정지 및 변경 사유를 관리합니다. 설정 변경에도 최고관리자와 2단계 인증이 필요합니다.

웹·워커에 필요한 서버 설정:

```text
TRON_NETWORK=nile 또는 mainnet
TRON_USDT_CONTRACT=Nile 테스트 토큰 (mainnet은 공식 USDT로 고정)
TRON_HOT_WALLET_ADDRESS=회사 수신 주소
TRONGRID_API_KEY=선택 (조회량이 많으면 설정)
TRON_FEE_LIMIT_SUN=계약 에너지 수수료 상한
CUSTODY_URL=격리 수탁 서비스 주소
CUSTODY_TOKEN=서버 인증 토큰
TRON_BROADCAST_ENABLED=true (명시적으로 전송을 허용할 때만)
SWEEP_REVIEW_SECRET=32자 이상, 또는 기존 CRON_SECRET 사용
DATABASE_URL 및 기존 검증된 TLS CA 설정
```

실제 개인키·니모닉을 웹/Vercel 환경이나 브라우저에 넣지 않습니다. 기존 Nile 개발용 서명 서비스는 분리된 `.env.custody`의 키를 사용하며 mainnet 서명을 거절합니다. mainnet 운영에는 같은 `/sign` 계약을 구현한 HSM/MPC 등 별도 수탁 서비스가 필요합니다. 신규 `kind: sweep_gas`는 승인된 회사→회원 TRX 보충만 서명하고 `kind: sweep`는 승인된 회원→회사 USDT만 서명해야 합니다.

지속 실행 서버에서 다음 중 하나를 서비스로 운영합니다.

```powershell
# 회수 전용: 입금 스캔 커서와 독립적으로 5초마다 승인 요청 처리
npm run worker:sweep

# 기존 통합 워커: 입금 감지·출금·회수 (입금 스캔 설정도 필요)
npm run worker
```

Next.js/Vercel 웹 배포만으로 지속 실행 워커가 생기지는 않습니다. Windows 서비스·컨테이너·프로세스 매니저 등에서 위 명령을 실행하고, 어드민의 워커 마지막 응답 시각을 확인하세요. 기존 통합 워커도 같은 새 회수 엔진을 사용하며, 입금 스캔 오류가 출금·회수 실행을 모두 막지 않도록 분리했습니다. 여러 워커를 실행해도 DB advisory lock으로 동시에 같은 회사 지갑을 처리하지 않습니다.

회사 주소 활성화, TRX 충전, 토큰·서명 서비스 설정 및 워커 준비를 마친 뒤 활성화합니다. 현재 설정이 부족하면 어드민에 부족한 항목을 표시하고 승인을 차단합니다. 설정 확인을 위해 실제 회수를 자동 실행하지 않습니다.

## 가스·재시도·회계

- USDT 잔액은 solidity API에서 조회합니다. 전송 시뮬레이션의 정확한 Transfer 이벤트를 확인하고 현재 `getEnergyFee`, `getTransactionFee`, 가용 Energy를 사용해 견적을 냅니다. Energy는 30% 여유분, Bandwidth는 1,000바이트분을 보수적으로 반영하며 회사 송금에는 계정 활성화 여유분도 둡니다. [TRON FeeLimit 문서](https://developers.tron.network/docs/set-feelimit).
- 워커는 승인 후에도 잔액과 비용을 다시 확인합니다. 승인된 보충 상한·현재 정책 상한을 초과하면 진행하지 않습니다. 가스를 한 번 보충한 후 부족해져도 추가 보충하지 않습니다. 남은 회원 TRX는 회수하지 않습니다.
- 검토는 서버 DB에 저장하고 HMAC으로 회원·관리자·만료 시각을 결합합니다. 승인 API는 브라우저가 보낸 수신 주소·금액·미서명 TX를 사용하지 않습니다.
- 승인 재요청은 같은 작업 ID를 반환합니다. 지갑당 하나의 활성 요청만 허용하고, 일괄 승인 중 한 지갑이라도 충돌하면 전체 요청을 롤백합니다.
- `sweep_outbox`에 미서명 TX/ID를 먼저 커밋 → 격리 서명 → 서명본 커밋 → 전송 순서입니다. 응답 유실은 같은 TX/서명본으로 재시도하며 새 송금을 만들지 않습니다. 서명 키 복구와 protobuf/주소/수량/수수료 검증을 수행합니다.
- TRX 보충은 확정 원본 TransferContract까지 대조합니다. USDT는 solid 영수증의 토큰·송신자·수신자·수량이 정확한 Transfer일 때만 완료됩니다. 전송 접수는 완료가 아닙니다.
- 만료·불명확한 TX는 **조사·검토 필요**로 보존하고 기존 TX 영수증만 계속 확인합니다. 이 요청이 해결될 때까지 후속 회수 큐도 대기합니다. RPC 오류·화면 새로고침 때문에 새 가스 보충이나 새 서명을 발행하지 않습니다.
- 서명/전송을 시작하지 않은 요청만 UI에서 취소할 수 있습니다. 서명 이후 요청은 원 TX를 체인에서 조사해야 합니다. 영수증의 확정 실패는 실패로 종료되어 새 검토가 가능합니다. 미확정 요청을 임의로 실패 처리하는 API는 제공하지 않습니다.
- 회수는 보관 자산의 위치 변경이므로 `balances`, `point_balances`, 회원 거래·저널을 변경하지 않습니다. 회사 지갑과 모든 회원 주소를 합산하는 기존 대사 방식은 유지됩니다.

기존 단순 회수 API는 새 검토 화면으로 안내하도록 막았습니다. 배포 전 생성된 미완료 요청은 새 서명 승인을 의미하지 않으므로 조사 필요로 전환하고 기존 TX 정보를 보존합니다. 서명 전이라면 취소 후 다시 검토할 수 있습니다.

## 저장소와 검증

원본 참고: `ibnetsoft/wallet` 커밋 `eb041f4674d6f92cd01be9e6541b8ac7913c60d2`의 `trc20-sweep*.ts`, `Trc20SweepPanel.tsx`, 관련 SQL과 `docs/trc20-usdt-sweep.md`. 원본의 회사키 DB 저장·TLS 검증 해제·mainnet 고정은 가져오지 않았습니다.

- `db/sweeps.sql`: 운영 설정·검토·서명 아웃박스·워커 상태·승인 함수·RLS. 기존 `db:apply`에 포함됩니다.
- `npm test`: native TRX/USDT 정확한 의도 검증, 서명 복구, 보충 응답 유실 후 동일 TX 재시도, 확정 송신자 대조, 만료 처리, 중복 승인, 중단, 회원 원장 무변경과 브라우저 권한을 검사합니다. 체인 어댑터를 모킹하며 네트워크 전송하지 않습니다.
- `npx tsx scripts/verify-sweeps.ts --test-account`: 임시 Supabase 계정으로 조회/접근 통제/최고관리자 AAL2/Origin 검증, 실제 PostgreSQL 승인·중복 방지·RLS를 롤백 전용 트랜잭션에서 확인합니다. 가상 회수 요청·주소·계정은 남기지 않습니다. 실제 서명·보충·USDT 브로드캐스트는 하지 않습니다.
- 브라우저 자동화 런타임의 파일 경로 오류로 화면 조작 검증은 수행하지 못했습니다. Nile에서 운영자가 소액 입금→검토→TRX 보충 확정→USDT 회수 확정→회원 앱 잔액 유지까지 확인한 후 실제 자산 운영에 사용하세요.

## TronGrid API 키 설정

관리자 콘솔의 **TRON API 설정**에서 TronGrid API 키를 등록하거나 교체합니다. 등록은 최고관리자 권한이 필요하며, 서버가 TronGrid에 키를 확인한 후 AES-256-GCM으로 암호화하여 저장합니다. 화면과 API는 등록 여부만 반환합니다. 서버는 DB 값을 우선하며 없으면 기존 `TRONGRID_API_KEY` 환경 변수를 사용합니다. 키 변경은 웹 인스턴스와 워커에 최대 30초 후 반영됩니다.

암호화에는 `TRONGRID_SETTINGS_ENCRYPTION_KEY`를 사용하며, 없으면 기존 `CRON_SECRET`을 사용합니다. **웹과 모든 워커에 동일한 암호화 비밀이 있어야 합니다.** 비밀을 변경하면 기존 키를 복호화할 수 없으므로 변경 전 재암호화 절차가 필요합니다. 개인키·니모닉을 이 설정에 넣지 마세요.


## 회사 지갑 외부 송금

관리자는 USDT 모으기 화면에서 메인넷 회사 지갑을 생성하고 공개 주소를 확인할 수 있습니다. 개인키는 서버의 암호화 비밀로 암호화하여 데이터베이스에 보관하며 화면이나 API로 반환하지 않습니다. 전용 암호화 비밀 `COMPANY_WALLET_ENCRYPTION_KEY`를 분실하거나 재암호화 없이 교체하면 자금에 접근할 수 없으므로 안전한 백업과 복구 절차가 필수입니다. 회사 지갑을 생성하면 DB가 메인넷 토큰에 결합됩니다.

최고관리자 2단계 인증 후 수신 주소, 수량, TRX 비용을 검토하고 확인 문구와 사유를 입력해 승인합니다. 송금 금액의 90% 제한은 없으며 잔액과 네트워크 수수료는 확인합니다. 요청별 트랜잭션은 저장 후 서명·전송하고 기존 TX만 재시도합니다. 유효기간이 지난 미확정 TX는 재서명하지 않고 확인을 기다립니다. `pg_cron`과 `pg_net`은 승인된 요청이 있을 때만 Vercel의 인증된 워커를 호출합니다.

이 회사 외부 송금 지갑은 기존 회원 회수·회원 출금용 `TRON_HOT_WALLET_ADDRESS` 설정이나 별도 수탁 워커를 자동으로 구성하지 않습니다. 메인넷 주소의 실물 전송은 별도 승인 후 진행하며 배포 검증에서 실제 송금을 실행하지 않습니다.
