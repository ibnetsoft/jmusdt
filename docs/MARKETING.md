# 상품별 마케팅 플랜

## 운영 방법

1. `/admin/shop`에서 가격과 함께 **상품 1개당 마케팅 보상**을 입력합니다. 0은 미지급입니다. 기존 상품은 전 항목 0으로 시작합니다.
2. `/admin/marketing`에서 신규 구매 보상 적용 여부, 데일리 일시정지, 보상 조회·검색, 미수금 확인 및 기한 도래 데일리 재처리를 관리합니다. 변경 사유와 버전을 감사 로그에 기록합니다.
3. 회원은 지갑의 **리워드·주머니** 링크(`/rewards`)에서 지급·예정·미지급·회수 내역과 보유 패키지 수량과 일배당 내역을 확인합니다.

| 상품 입력 항목 | 단위 | 구매 시 처리 |
|---|---|---|
| 추천리워드 | 고정 P | 구매자의 직접 추천인에게 지급 |
| 후원리워드 | 고정 P | 구매 시 배치된 후원인에게 지급 |
| 맘리워드 | 고정 P | 후원인의 직접 추천인에게 지급. 후원리워드가 실제 지급된 경우만 발생 |
| 복주머니P | 정수 P | 회사 일일 풀에 적립 후 해당 패키지 보유 수량에 따라 분배 |
| 보물상자P | 정수 P | 회사 일일 풀에 적립 후 해당 패키지 보유 수량에 따라 분배 |
| 데일리수당 | 하루 P + 지급 일수 | 구매 다음 날부터 한국 시간 날짜별로 구매자에게 지급 |

모든 항목은 구매 수량을 곱합니다. 포인트는 6자리 소수 정밀도를 유지합니다. 데일리는 최대 369일이며 금액과 일수를 함께 0 또는 양수로 입력합니다. 일일 풀 적립은 종류별 상품당 최대 1,000,000 P입니다. 패키지 소지자에게 일반 포인트로 분배합니다.

일반 상품의 추천+후원+맘+(하루 데일리×일수)+회사 적립 합계는 상품 가격을 초과할 수 없습니다. 예: 가격 100 P, 추천 10 P, 후원 5 P, 맘 3 P, 데일리 2 P×3일이면 총 보상 예산은 24 P입니다. 두 개 구매 시 각각 두 배로 처리됩니다. 복주머니P와 보물상자P의 회사 적립액도 상품 가격을 초과하지 않도록 포인트 예산 합계에 포함합니다.

보상 수령인이 없거나 정회원 자격·이메일 인증·정상 계정 조건을 충족하지 못한 경우 직접 보상은 미지급 사유를 기록하고 매출에 남깁니다. 본인에게 돌아오는 추천·후원·맘은 제외합니다. 추천인과 후원인이 같은 회원이면 추천·후원 항목을 각각 받을 수 있습니다. 맘은 후원인 자신과 구매자 자신에게 지급하지 않습니다. 구매 당시 후원 위치가 없었다면 이후 배치해도 소급 지급하지 않습니다.

상품·관계·운영 설정 버전을 주문에 스냅샷으로 저장합니다. 상품 수정은 이후 구매에만 적용됩니다. 신규 구매 보상 적용을 꺼도 과거 주문의 권리는 유지됩니다. 이전 USDT 주문에는 새 포인트 보상을 적용하지 않습니다.

## 데일리 자동 지급

Vercel Cron은 `0 15 * * *`(UTC), 한국 시간 매일 00:00에 `/api/cron/marketing`을 호출하도록 등록합니다. 일일 풀도 같은 호출에서 마감하며 플랫폼 요금제에 따라 실제 실행 시각에는 지연이 있을 수 있습니다. 서버 전용 `CRON_SECRET` Bearer 인증이 필요하며 공개 요청은 401입니다. 비밀 값은 저장소나 브라우저에 포함하지 않습니다. 일일 풀의 현재 동작은 [일일 분배 안내](DAILY_POOLS.md)를 따릅니다.

날짜는 `Asia/Seoul` 기준이며 지급일이 도래한 미지급 회차만 처리합니다. 중복 실행·누락일 재실행은 추가 지급하지 않습니다. 일시정지·일반회원 전환·회원 차단·취소 요청 상태에서는 데일리를 보류하고, 재개·차단 해제·취소 반려 후 밀린 회차를 처리합니다. 취소 확정 주문은 지급하지 않습니다.

한 DB 실행은 최대 100주문/500회차, Cron 요청은 최대 10회/시간 제한 내에서 처리합니다. 큰 누적 지연은 이후 실행 또는 관리자의 재처리 버튼으로 나누어 지급합니다. 이 구조는 현재 규모용이며 처리량이 커지면 지속 실행 워커로 옮길 수 있습니다.

## 취소·회수와 회계

구매의 주문·재고·포인트 차감·보상 지급·데일리 권리 및 준비금 적립은 하나의 DB 트랜잭션입니다. 동일 구매 요청은 보상을 다시 생성하지 않습니다. 보상은 회사 매출에서 배분하며 데일리 총 지급 예정액은 `marketing:reserve`에 보관합니다. 구매·환불·데일리 처리에는 같은 트랜잭션 advisory lock을 먼저 잡아 회원 간 교차 지급을 직렬화합니다.

기존 주문 취소 승인에 자동으로 연결됩니다.

- 구매 대금 전액을 원 결제 자산으로 반환하고 재고를 복구합니다.
- 지급한 추천·후원·맘·데일리 포인트를 수령인의 잔액에서 회수합니다.
- 이미 사용한 부족분은 `marketing_debts`에 회수 미수금으로 기록합니다. 이후 보상·USDT→포인트 전환·포인트 환불 등 포인트 유입에서 자동 상계합니다. 전환 이력의 총액과 별도로 실제 사용 가능한 포인트가 줄어들 수 있으며 전환 화면에서 안내합니다.
- 남은 데일리 권리를 취소하고 준비금을 매출로 돌립니다. 분배 전 일일 풀 적립액은 취소하며 패키지 주문이 취소되면 이후 미분배 마감의 자격도 제외합니다.
- 취소 재승인은 추가 환불·추가 회수하지 않습니다. 원 거래·저널은 수정하지 않고 반대 분개를 추가합니다.

미수금이 발생해도 구매자의 취소 승인을 막지 않습니다. 수령인에게 향후 포인트 유입이 없다면 미수금이 남을 수 있으므로 어드민에서 확인해야 합니다. 이미 출금된 자산을 자동으로 되돌린다고 표시하지 않습니다.

대사 예상액은 회원 USDT·포인트 잔액 + 수수료 + 쇼핑몰 잔여 매출 + 데일리 준비금 - 보상 미수금입니다. 패키지 보유 수량은 포인트 잔액에 포함하지 않으며 미분배 회사 풀 준비금은 대사에 포함합니다.

## 권한·구현

상품 및 마케팅 설정은 기존 서버 `adminConsole` 권한으로 관리하며, 회원은 본인 보상·미수금만 조회할 수 있습니다. 기존 온체인 자금 작업의 SUPER_ADMIN/AAL2 조건은 유지합니다. 정책을 핑계로 임의 포인트를 증액하거나 지급액을 수정하는 API는 제공하지 않습니다.

`db/marketing.sql`은 RLS와 브라우저 SQL 실행 권한 제한을 포함하며 `npm run db:apply`에서 적용합니다. 주요 테이블은 `marketing_settings`, `marketing_rewards`, `marketing_debts`입니다. 상품의 `reward_plan`과 주문의 `reward_snapshot`으로 입력값과 적용값을 구분합니다.

현재 정책은 사용자가 2026-10-28 정정한 내용을 우선합니다. 추천·후원·맘은 실시간 포인트 지급, 데일리·복주머니·보물상자는 한국시간 자정 일배당입니다. 강사보너스와 직급보너스는 제공하지 않습니다. 모든 수당은 일반 포인트(P)이며 원화 지급·계산은 없습니다. 상품별 수동 고정 포인트 금액은 유지합니다. 후원 배치는 [조직도 안내](ORGANIZATION.md)의 정회원 등록순 3·6·9 롤업을 사용합니다. 정회원 자격은 [회원등급 안내](MEMBER_GRADES.md)를 따릅니다.

`db/marketing.sql`은 기본 스키마이고 실제 현재 보상 함수는 뒤에 적용되는 `db/daily-pools.sql`로 재정의합니다. 신규 설치·업데이트 모두 전체 `npm run db:apply` 순서를 사용해야 합니다.

## 검증

- `npm test`: 구매 수량·6자리 정밀도, 여섯 항목, 관계·정책 스냅샷, 예산 상한, 중복 구매·지급·취소, 데일리 보류·재개, 미수금 분할 상계, 차단 수령인 및 브라우저 권한을 확인합니다.
- `npx tsx scripts/verify-marketing.ts --test-account`: 실제 Supabase 임시 회원으로 관리자 상품 설정/예산 검증·인증·접근 통제를 확인합니다. 실제 PostgreSQL 보상·데일리·환불·미수금 검증은 롤백 전용 트랜잭션에서 실행하고 계정·상품을 정리합니다. 합성 자금·주문·보상을 남기지 않습니다.
- 기존 `verify-commerce.ts`의 이미지·상품·구매·전환·환불 회귀 검사와 타입 검사·프로덕션 빌드를 실행합니다.
- 새 자동 배치·일배당 규칙은 `network-rollup.test.ts`, `daily-pools.test.ts`에서 전체 마이그레이션 조합으로 검증합니다. 기존 기본 스키마 테스트도 회귀 검사로 유지합니다.

## 369일 패키지 확정 상품

- 복주머니 패키지: 350,000 P, 데일리 1,000 P × 369일, 총 369,000 P.
- 보물상자 패키지: 3,500,000 P, 데일리 10,000 P × 369일, 총 3,690,000 P.
- 두 상품의 추천·후원·맘 리워드와 회사 복주머니P·보물상자P 적립은 모두 0이다. 기존의 회사 적립금 수량별 1/N 배당 참여 자격은 유지한다.
- 이 두 패키지 종류·가격·정확한 데일리 전용 플랜에 한해 판매가를 넘는 총 지급액을 허용한다. 일반 상품과 다른 초과 보상은 계속 차단한다. API와 DB의 패키지별 검증 조건이 같다.
- 지급 예정액 전체를 구매 시 준비금으로 잡는다. 판매가 초과분 19,000 P / 190,000 P는 회사 매출의 음수 약정액으로 드러나며, 이를 숨기거나 외부 입금으로 가장하지 않는다. 기존 대사의 회사 매출 항목에 반영된다.
- `db/package-daily-369.sql`을 `db/daily-pools.sql` 다음에 적용한다. 기본 스키마 재실행 시 패키지 검증 제약을 옛 판매가 한도로 되돌리지 않는다. 기존 주문의 보상 스냅샷·지급 일정은 변경하지 않는다.
